# 个人健康档案室 · 产品设计（v1）

基于 `档案/` 本地基建。网站尚未开发；本文约定「你要看什么」和「怎么维护」。

---

## 1. 你真正需要的不是「所有指标」，而是三条线

结合你现有资料（过敏性紫癜随访、尿系复查密集、中药方另线、张悦档案隔离），网站应对你回答：

1. **我最近为什么去医院？** → 看病目的时间线  
2. **关键指标是变好还是反复？** → 关注指标趋势（不必全量 OCR）  
3. **某次检查原文在哪？** → 按次归档的检查详情 + 原图

门诊单、购药记录以后挂到同一套「事件」上，档案室就完整了。

---

## 2. OCR 策略建议：异常优先 + 关注清单（推荐）

| 方案 | 做法 | 适合你吗 |
|------|------|----------|
| A 全量 OCR | 每张单所有指标入库 | 成本高，噪音大，多数正常项你不会看 |
| B 只 OCR 异常 | 只收报告上标 ↑↓ / 阳性 的项 | 轻，但「从异常变正常」的点会丢，趋势断档 |
| **C 异常 + 关注清单（推荐）** | 异常必收；另维护 8～15 个「关注指标」，每次同名检查都尽量抽出（正常也收） | 最贴合「追踪同一指标变化」 |

### 建议的第一批关注指标（紫癜/肾随访）

- 尿：蛋白质(PRO)、潜血(BLD/ERY)、红细胞(RBC)、白细胞(WBC)、尿蛋白/肌酐、尿微量白蛋白/肌酐(ACR)  
- 血：IgA、C1q、TBIL/DBIL、CRP、血沉、WBC/PLT（血常规里挑关注的）

其余指标：报告上有异常才入库；详情页仍可看原图核对。

### 数据字段补充（相对现有 schema）

每条 `records[]` 增加：

- `purpose`：看病目的（短标签，可空）  
- `purpose_note`：一句说明（可空）  
- `event_id`：可选，把「同一天/同一次就诊」的多张单捆成一个事件  

`indicators` 增加：`is_abnormal`、`is_watched`（是否命中关注清单）。

## 3. 看病目的：怎么打、怎么来

### 标签库（可增改）

| 目的标签 | 典型材料 |
|----------|----------|
| 过敏性紫癜随访 | 绝大多数尿常规/尿蛋白肌酐比/免疫生化 |
| 风湿免疫排查 | 2024-03-07 一批 ANCA、狼疮、抗磷脂等 |
| 中药调理-怕冷手足汗 | 中药方 |
| 年度体检 | 体检报告 |
| 其他/未标注 | 找不到参考时留空 |

### 打标规则（第一版可半自动）

1. 读病史 Word 里的时间线关键词 → 落在区间内的检验默认「过敏性紫癜随访」  
2. 中药方目录 → 默认「中药调理-怕冷手足汗」  
3. 体检 PDF → 「年度体检」  
4. 对不上的 → `purpose=""`，你在网站上手改  

同一天多张单（如 2024-03-07）共享同一个 `event_id` + 同一目的，避免重复。

## 4. 网站信息架构（所有者可见）

侧栏新增：**健康档案**（仅 owner）

### 4.1 总览页 `/health`（打开先看这个）

一块屏回答「最近身体故事」：

- **近况卡片**：最近一次检查日期、最近目的、当前关注指标里仍异常的个数  
- **目的分布**：紫癜随访 / 中药 / 体检 各多少次（简单条或芯片）  
- **关注指标快览**：每个关注指标最新值 + 相对参考区间状态（正常/偏高/偏低）+  sparklines（小趋势）  
- **最近 5 条事件**：日期 · 目的 · 检查名称摘要 · 进详情  

不要做成仪表盘堆砌；总览只服务「要不要点进去」。

### 4.2 时间线页 `/health/timeline`

按日/按就诊事件纵向排列（类似生活日志）：

- 日期徽章 + **看病目的**（主标题）  
- 当天材料：检验芯片、中药方、门诊、购药（图标区分）  
- 异常摘要一行：「潜血++ · RBC↑」  
- 点进去 → 事件详情  

筛选：目的、检查类型（尿/血/方/药）、年份。

**这是你最常刷的页**——比纯「历次检查目的列表」更自然。

### 4.3 趋势页 `/health/trends`

- 先选关注指标（或检查名：尿常规）  
- 折线：时间 × 数值；异常点高亮；参考区间带状可选  
- 下列表：每次日期、值、是否异常、关联目的、链到原单  

没有 OCR 的点显示「仅有原图，未结构化」——不造假数据。

### 4.4 档案库页 `/health/records`

表格/卡片：日期、目的、检查名、医院、标本、异常数、维护状态。  
上传入口、批量改目的、绑定到事件。

### 4.5 单条详情 `/health/records/<id>`

- 左/上：原图或 PDF 预览  
- 右/下：目的（可编辑）、检查名、医院、日期  
- 指标表：关注项置顶，异常标色；支持手改纠错  
- 「加入关注」「标记仅异常已收录」

### 4.6 维护页 `/health/settings`（轻量）

- 目的标签库增删改  
- 关注指标清单  
- OCR 策略开关：仅异常 / 异常+关注  
- 人物：本人默认；张悦档案可隐藏或单独开关（建议默认不进主时间线）

## 5. 维护功能（上传 → 数据化 → 可改）

统一流程（检验单 / 门诊单 / 购药都走同一套）：

1. **上传**：图片/PDF → 存 Volume（`/data/health/...`）  
2. **建档**：文件名或 OCR 头信息抽日期、检查名、医院  
3. **目的**：自动建议 + 你确认  
4. **结构化**：按策略抽指标（可后台任务，失败可重试）  
5. **手改**：所有字段可编辑；改指标后趋势即时变  
6. **归并事件**：勾选同日多单「合并为一次就诊」  
7. **软删**：进回收，不直接抹盘（符合你「不丢数据」习惯）

购药/门诊第一版字段建议：

- 门诊：日期、医院、科室、主诉/目的、诊断、附件  
- 购药：日期、药名、剂量用法、关联目的、附件

## 6. 界面优先级（建议落地顺序）

| 阶段 | 做啥 | 你立刻能感到的价值 |
|------|------|-------------------|
| P0 | 时间线 + 上传建档 + 目的手填/半自动 | 档案「能翻、能找」 |
| P1 | 详情原图 + 关注指标手填/少量 OCR | 开始能看尿蛋白/潜血是否反复 |
| P2 | 趋势图 + 异常自动抽取 | 「变好了没有」一眼看 |
| P3 | 门诊单、购药 | 健康档案室成形 |
| P4 | 张悦分区、导出 PDF 健康摘要 | 可选 |

## 7. 直接回答你的犹豫

- **要不要 OCR 全部指标？** 不建议。用 **异常 + 关注清单**。  
- **趋势还是目的？** 两个都要，但 **时间线（目的驱动）是首页主叙事**，趋势是专题页。  
- **这些数据能展现什么？**  
  - 紫癜随访是否规律、尿红/蛋白是否反复  
  - 哪次是大排查（如 2024-03-07）、哪次是复查  
  - 中药调理与西医随访是否并行  
  - 以后：用药是否跟症状/检验变化对得上
